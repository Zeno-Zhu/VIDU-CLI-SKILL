## 零、先想清楚：这一篇在砍什么

大纲的本质是**做减法**。但减的对象看来源：

| `origin` | 输入 | 「砍线」砍的是什么 |
| --- | --- | --- |
| `novel` | 一部小说原文 | 小说的情节线。砍到只剩一条主线 + 至多一条副线 |
| `original` | 一个脑洞 / 一句创意 | **脑洞的可能性**。它可以是喜剧、可以是复仇、可以是温情——先摊开，再砍到一条 |

`original` 模式下最容易犯的错：把所有可能性都留下，结果每条都只走一步。**一个脑洞只能撑一部剧的一种走向。**

---

## 一、顺序就是方法（五步，不能跳序）

### 第 1 步｜砍线

短剧只装得下**一条主线 + 至多一条副线**。

- 砍掉的写进 `adaptation.cut`，每条都要有 `why`。
- `origin=novel` 且 `adaptMode` 不是「忠实」时，`cut` 不能为空——一条不砍 = 没改编。
- 砍完补一句 `cutNote`：**「这意味着：全剧终点是……」** 说清砍完之后故事的终点变成了什么。

> `cutNote` 不是形式。它是给用户拍板时看的第一句话。写不出这句，说明你还没想清砍完剩下什么。

### 第 2 步｜合人

功能重复的角色合成一张脸（两个报信的 → 一个），合并记录写进 `characters[].from`。

然后**分档**：

| `tier` | 是谁 | 上限 | 规则 |
| --- | --- | --- | --- |
| `lead` | 主角组（男女主 + 主反派） | 1–5 人 | `arc` 必填 |
| `support` | 有名字的重要配角（亲属、闺蜜、副反派） | ≤10 | `arc` 必填 |
| `functional` | 功能性角色（医生、秘书、店员） | ≤10 | **占脸不占名**：`name` 用称呼标签（「急诊医生」）；`arc` 可省 |

无名背景人不进表、不追踪、不限量。

**这一层还要定 `anchor`**——这是无限轮回独有的：

```
base:wanji   男主万集本世身份    恰好 1 个（必须）
base:suwei   女主苏薇/锚点本世身份  ≤1 个；coreValue 含爱情/甜时必须存在
system       系统精灵            ≤1 个
local        本世界原创角色       不限
```

合完补一句 `mergeNote`：主角组入选理由（谁有完整转变弧）。

### 第 3 步｜收场景

主场景上限随集数动态：`4 + ⌈集数/10⌉`，夹在 5–15（6 集 → 5 个，60 集 → 10 个）。

这是按 AI 短剧定的宽松版——场景是生成的，没有搭景钱，多开几个景换观赏性是划算的。别把戏都憋在一个屋里。

**原著/设定里只出现一次的场景**，要么砍掉，要么写 `reusePlan`（复用哪个现有环境资产、换什么时段天气改出来）。

### 第 4 步｜排爽点（观看价值曲线）

先定 `major`（大爆点）落在哪几集，再拿 `minor` 填缝。

**硬规则：**

- 相邻爽点间隔 ≤ 3 集
- 开头结尾无真空
- 至少一个 `major`，且最早的 `major` 不能落在最后一集

**每条 beat 要写三个东西：**

| 字段 | 写什么 |
| --- | --- |
| `value` | 观看价值类型：爽 / 笑 / 甜 / 痛 / 怒 / 奇观 / 悬念 / 反差 / 成长 |
| `setup` | 前面怎么铺 |
| `payoff` | 具体兑现成什么场面 |

`params.coreValue` 里声明的每一项，在 `beats[].value` 里都要有足够次数（每 10 集至少 1 次）。**这条会被 `core-value` 门拦。**

如果本篇要用到世界意志或终极秘密，在 beat 上标 `reveal`；`params.mainline=false` 时不许标——**`mainline-bound` 门会拦**。

### 第 5 步｜收道具

**排在爽点之后不是随便排的**——叙事道具的判据是「它托起哪个爽点」，爽点没定就分不清哪件物件是道具、哪件只是陈设。

上限 8 件，跟主角数量一个量级。

**一件东西该不该进这张表，问一句就够：它坏了、丢了、被换掉，剧情会不会塌？**

会塌 → 叙事道具（皮箱、砚台、那封信）。不会塌 → 场景陈设（船舱的挂灯、桌上的茶碗）。

**填不出 `function` 的一律不收。填不出来的不是道具，是背景。**

## 二、两轮规则 ⛔

骨架必须跑两轮。

### 第一轮：快版

四块填齐、能过 `validate --stage beats` 就停，**交给用户拍板**。

**拍板三件事：**

1. 砍了哪条线（或：这个脑洞只走了哪一条）
2. 合了哪些人
3. 大爆点落在第几集

**这三件事用户不点头，后面全是白干。**

快版的意义是便宜——错了只损失一轮骨架，不是 60 集梗概。

### 第二轮：细版

吸收用户意见后细化，再过一次 `validate --stage beats`。用户没意见就直接进分集。

---

## 三、分集梗概（每批 ≤ 10 集）

骨架拍板之后才有这一步。

**每集三栏，缺一栏就是没写完：**

| 栏 | 写什么 |
| --- | --- |
| `synopsis` | 这一集发生了什么。**叙述体**——出现 `「」“”` 引号对白就是在写剧本，`prose` 门会拦 |
| `hook` | 【钩子】让人点下一集的那个问题 |
| `suspense` | 【悬念】埋着没解的线 |

### 硬规则

- 落在你区间里的每个 beat（`beats[].episode`），对应那一集的梗概必须真的把 setup/payoff 演出来
- `sceneIds` / `characterIds` 只能用骨架里登记过的 id
- **三人以上同框写 `crowdPlan`**（拆解方案：谁在前景说话、谁在背景反应）。校验按 `characterIds` 人数判，是代理指标——三人实际不同框的过场集，把事实写成方案即可（「三人分处两场，无同框，分场拍」）
- 梗概里出现**雨、拥抱、人群、手部特写**这类生成难点，写进 `warnings`。宁可多报
- 只写你负责的区间，别越界补别人的集

### 批次纪律

每批 ≤ 10 集。60 集一口气写，后半段一定崩——节奏塌、钩子重复、人物漂移。

批与批之间靠**骨架和爽点表**对齐，不靠上一批的原文。

## 四、常见病

| 病 | 症状 | 治法 |
| --- | --- | --- |
| 全都要 | 每条线都留一点，每条都只走一步 | 回到第 1 步，只留一条 |
| 角色膨胀 | 40 集出了 30 个有名有姓的人 | 功能重复的合脸，无名的降为 `functional` 或直接不进表 |
| 场景漂移 | 每集都换新景，观众记不住空间 | 收场景，一次性场景写 `reusePlan` |
| 爽点真空 | 中间连续 5 集没爆点 | 补 minor，或者把后面的 major 前移 |
| 商品失焦 | 大纲说要甜，全篇在打架 | 看 `coreValue` 与 `beats[].value` 是否对得上 |
| 主线偷跑 | `mainline=false` 却在第 40 集揭世界意志 | 改成候选设定，或明确改 `mainline=true` |
| 梗概写成剧本 | 三栏里全是引号对白 | 改叙述体，对白留给阶段 C |

## 五、自检

```
node {baseDir}/scripts/ir-outline.mjs validate outline.json --stage beats
```

有违规逐条修，改完重跑，**直到通过才允许进分集**。

交付前再跑一次 `--stage full`。
