# 00 · 流程总表（P0–P10）

> 每一步只有三种形态：**脚本（可判定）**、**AI 创作（标注需人工）**、**用户确认**。
> 没有第四种「写在文档里指望模型遵守」的软约束。
> 确定性分级见 `15-确定性.md`。

## 三个零 LLM 环节（这次重构的重点）

```
P6  bind_assets.py     分镜组表 + 资产清单 → 绑定表（pn 唯一来源，冻结 hash）
P7.5 prompt_assemble.py 绑定表 + 草稿 → 终稿（pn 块/强制声明/禁用句 由脚本注入）
P8  jobs_build.py      绑定表 + 终稿 → 作业单（images 顺序逐字抄绑定表）
```

**为什么必须零 LLM**：pn 是「第几张图配哪个角色」，属于可判定事实，不是创作。
交给模型 = 每次都可能换一个顺序 = 必然错绑。

---

## 每步的进入 / 跳过

- **已有且通过门** ⇒ 跳过；⛔ 不因为「流程里有」就重跑。
- 跳过前先跑该步的检查器；检查器 0 = 可跳，2 = 必须重做。
- 任何一步改了上游 ⇒ 下游全部重建；`bind_check.py` 的 hash 会拦住旧稿。

---

## 失败处理原则

| 失败类型 | 处理 |
|---|---|
| 结构错（缺字段 / 重名 / 编号冲突 / 文件不存在） | **BLOCK（退出码 2）**，修到 0 再往下 |
| 创作质量问题（景别平 / 表演不对 / 峰值选错） | **L0，人工判**，不进硬门 |
| 单组超标 / 缺资产 / pn 不连续 | 只重做**那一组**，其余逐字不动 |
| 出片失败 | 按台账分类（资产 / 提示词 / 额度），只重跑受影响组 |

---

## 一句话

**P0 定参数，P2 定资产，P5 定结构，P6 定绑定，P7 只写戏，P7.5/P8 只注入；需要剪映草稿时再走 P9.5。**
