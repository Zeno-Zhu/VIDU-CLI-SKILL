# 做一张符 / 用一张符

符 = 把一类 AI 视频能力压成一张 16:9 的图。

说白一点：**符就是 AI 视频的 skill，只不过 skill 的载体是文字，符的载体是图。** 本来要几千字讲清的经验、要点、禁忌、错法，压成一张图，让模型直接看。模型读图比读长文本准——不会被截断，不会抓错重点，不会把第三条要点当成装饰。

**图是能力卡，不是海报。** 它要能让下游模型照着做，不是让人点赞。

---

## 什么时候用这个文件

管两件事：**做符**（前五步）和**用符**（最后几节）。两件事都**用户主动提才做**。

| 用户说 | 你做什么 |
|---|---|
| 「做个符」「把太极拳做成符」「封装一下这个技巧」 | 做符，走第一步往下 |
| 「来一张运镜的符」「世界观风格做成符」 | 做符 |
| 「用我的符做」「带张运镜的符」「用你自带的那几张」 | 跳到「用符」那节，先回主线 |
| 「这类动作每次都崩」 | 先查库；有对症的就挂，没有才提议做一张 |

**别主动推销符。** 用户没提，就当这个文件不存在。新手第一次做片，全程不该听见「符」这个字。

**符不是视频。** 做符做完就交图，不提交视频任务，也不进分镜。

---

## 第一步：收料（只问一句）

| 他给的 | 你要什么 |
|---|---|
| 通用主题（太极拳、推镜、赛博朋克） | 够了，直接做 |
| 他自己的方法 / 新梗 / 某个片的某个镜头 | 要材料：参考图、案例、他自己的一句话经验 |
| 只丢来一张参考图 | 问：这张图里，你想让我保住的是哪一件事？ |
| 什么都说不清 | 问：这东西是治什么毛病的？一句就行 |

问法就一句：

> 这个能力是解决什么问题的？一句话——模型现在做不好的是什么。

**别问**：分几栏、什么配色、字多大、要不要参数表。规则里已经定死了。

---

## 第二步：封装（照规则做，别自创格式）

`prompts/符的生成.txt` 是这套东西的系统规则，**整份读，按它的工作流走**。

它已经定死了几件事：

- 先定「有效标准」——这个能力解决什么问题、什么结果算成功
- 从案例里抽机制，不是抄案例的样子
- 分清「必要变量」（改了能力就废）和「开放变量」（改了只是换个样子）
- 一张 16:9 只装一个能力，装不下就砍范围，不许缩字号硬塞
- 示意人物只能黑白线稿 / 剪影，不许出现写实脸

它给的输出是两个代码块：

1. **JSON**：`name` / `type` / `intro`（≤60 字）/ `prompt`（≤100 字，下游调用指令）
2. **视觉 Brief**：必须以「技能/知识面板设计需求」开头

这两个不是给用户看的成品，是生图的原料。

**他要是只要提示词、不要图，到这里就停**，把两个代码块给他。

### 上游还有一份：符的方法论

`符的生成.txt` 管「怎么把经验萃取成面板」。**它没管的三件事**在 `references/符的方法论.md`：

- **符有父系**：从总纲符拆出来的、从翻车图反着做的，`meta.json` 要记 `parent`
- **一张符装不下**：量化闸是 6—7 个信息区块，超了先删、再收窄、最后才拆篇
- **做完算不算合格**：三道闸，脚本 success 只管第一道

**要管「一类能力」而不是「一件事」时**（比如运镜总纲），用总纲符写法：A 共同遵守 + B 差异化轴 + 反趋同铁律。见方法论第四节。

---

## 第三步：落盘 + 转成生图提示词

存到 `out/符/符-<能力名>/`：

```
meta.json     第一个代码块，原样存（入库就用它）
brief.md      第二个代码块，原样存（以后改符、拆符都靠它）
prompt.txt    真正丢给生图模型的（见下）
panel.png     出图后自动落这里
```

**meta.json 里的两个管理字段：**

```json
{
  "name": "推镜头",
  "type": "指定作用技能面板",
  "intro": "……",
  "prompt": "……",
  "status": "候选",
  "parent": "符-镜头调度"
}
```

- `status`：`候选` / `定稿` / `弃用`，**默认候选**。做完不是定稿，用户点头了才改。`lib --status 定稿` 只看能用的。
- `parent`：总纲符 ID、翻车图路径、原符 ID。没有就留空，**别编**。上游改了，下游要复核。

**为什么中间要过一道 prompt.txt**：brief 是给人看的两三千字结构化文档，直接喂生图模型会被截断、抓错重点。

prompt.txt 只留五段，1500 字以内。**开场语和尾缀不用你写**——`card` 会自动补上并把补好的版本写回 prompt.txt。

```
16:9 的 AI 视频技能知识面板，简体中文，字迹清晰。

标题：太极拳·掤捋挤按

必须出现的文字（逐字照抄，不要改字、不要漏字）：
1. 掤：前臂撑圆，力道向外，肘不过肩
2. 捋：顺对方来力侧引，重心后坐
3. 挤：两臂相合向前挤，劲从脚起
4. 按：双手下按，沉肩坠肘，意到脚底
5. 错法：只用手臂发力，胯不动

必须画对的关系（用黑白线稿小人）：
- 掤：前臂弧线与身体的夹角
- 捋：重心从前往后移动的方向箭头
- 挤：双脚蹬地 → 腰 → 前臂的力线
- 按：肩、肘、手依次下沉的竖向顺序

人物一律黑白线稿 / 剪影，不要五官、不要具体服装、不要写实脸。

版式、配色、图标、信息层级你自由设计，要求一眼能看到标题和四条要点的先后关系。
```

三条经验：

1. **文字是要点，不是段落。** 一条超过 20 个字就砍。
2. **「逐字照抄」这四个字必须写。** 不写，模型自己改写你的术语。
3. **人物约束要写两遍**（规则里一次、视觉说明里一次）。只写一遍，它照样给你画一张写实脸。

**改字重跑时，只动中间那段。** prompt.txt 是三块：开场语 → 你的正文 → 尾缀。前后两块别删也别改。

## 第四步：生图（生完自动进库）

```bash
python scripts/vidu.py card --name 太极拳 \
    --prompt-file out/符/符-太极拳/prompt.txt \
    --meta out/符/符-太极拳/meta.json \
    --tag 动作 --tag 教学
```

- 固定 16:9，出图存 `out/符/符-太极拳/panel.png`
- **`--meta` 一定要给**：库里靠它知道这张符「管什么、什么时候调」
- `--tag` 一个符两三个就够（动作 / 运镜 / 风格 / 情绪 / 对话戏）
- 有参考图（画风、版式想照着来）：加 `--ref 参考图.png`，可重复
- 文字糊：加 `--resolution 2k`；报 `Invalid resolution` 就退回默认
- 不想进库：加 `--no-lib`

**尾缀别乱加。`card` 默认 `mid`（归约细节，灭高频冗余），这个是对的。**
`full` 含「软泛焦均质简谐流」，会把面板上的小字糊掉。符的第一硬标准是每个字都能读。
真要更锐，往 `min` 走，不是往 `full` 走。

**生图不走闲时额度，走积分（6 积分/张）。** 开工前 `check` 看一眼余额；`--dry-run` 先报价。

---

## 第五步：看三件事（最容易漏）

| 看什么 | 不对怎么改 |
|---|---|
| 中文错字、漏字、繁简混 | 打开 prompt.txt，把错的词单独拎出来写「必须逐字准确」，重跑 |
| 冒出写实人脸 / 具体角色 | 补一句「人物仅黑白线稿或剪影，无五官细节、无服装造型」 |
| 塞太满、字小到看不清 | 别调字号，砍内容：留 3 条要点；还不行就拆两张 |

**最多重跑 3 次。** 三次还错字，不是模型的问题，是这张符想讲的东西太多，砍一半再来。

---

## 交付：图 + 三行字

```
符名：太极拳·掤捋挤按
管什么：让模型生成太极动作时不乱、不软、不抢拍
什么时候调：写打斗 / 教学 / 慢动作镜头时，把这张图当参考图带上
```

完整 brief 不用贴给用户，太长。存着，下次改符直接改它。

## 符库：自己做的都在 out/符

```
out/符/
  _库.json              总索引
  符-太极拳/
    panel.png           成品，唯一会被当参考图传出去的那张
    meta.json           名字 / 类型 / 简介 / 调用指令
    brief.md            完整视觉 Brief
    prompt.txt          生图实际用的提示词
```

> 本包**不含内置符库**。需要哪一类能力，按下面的流程自己封一张，做完一样进库。

```bash
python scripts/vidu.py lib                  # 全列出来
python scripts/vidu.py lib --q 太极          # 搜名字 / 简介 / 标签
python scripts/vidu.py lib --tag 运镜        # 按标签筛
python scripts/vidu.py lib --status 定稿     # 只看能用的
python scripts/vidu.py lib --show 符-太极拳   # 看一张的详情（含调用指令原文）
```

补录和移除：

```bash
python scripts/vidu.py lib --add out/符/符-运镜   # 手做的符补进库
python scripts/vidu.py lib --rm 符-运镜           # 只动索引，不删文件
```

库跟着脚本走：skill 装在哪，库就在哪。想共用一个库，设 `VIDU_CARD_ROOT`。

## 用符：符怎么进提示词

用户说「用我库里的符做」「带张运镜的符」时走这里。

**这不是另开一条线。** 就待在主线里，照常读剧本、盘资产、拆分镜组，只在**写提示词那一步**拨一下开关。

符是一张**参考图**，不是贴在画面上的东西。它告诉模型「这类事按这套规则做」——原来你要写三百字讲运镜怎么推，现在挂一张图 + 一句调用指令。

**但它不能替你写画面。** 人在哪、光从哪来、动作怎么走，该写还得写。符省的是「讲道理」的字，不是「写画面」的字。

### 四步

1. **查库，别猜。** `lib` 列出来，把命中的念给用户：名字 + 管什么。两张都像就让他挑
2. **挑 0—2 张。** 多了模型会打架；一张都挑不出来，就别挂
3. **写进提示词**（三层，见下）
4. **当参考图传，永远放在 `--image` 最后一位**

### 写进提示词：三层

**第一层：登记成图片资产。** 【资产盘点】加一行，编号接在道具后面。

```
人物视觉资产：pn1,男主=@
场景资产：pn2,饭馆=@
道具资产：pn3,旧怀表=@
技能参考资产：pn4,符-常用运镜=@
```

**第二层：加【技能调用】块，把调用指令原样抄。**

调用指令在 `_库.json` 的 `call` 字段，`lib --show 符-常用运镜` 能看到，源头是 meta.json 的 `prompt`。**一字不改地抄，别改写、别概括。**

```
【技能调用】
pn4,符-常用运镜=@
调用指令：写推／拉／摇／移／跟／升降／环绕，或出现运镜重复、镜头死板时调用；按本卡先定任务再选运镜、每个运动写清起点路径与落点，画面内容照本条提示词。
禁用：本卡不在画面中出现——不出现面板、文字块、图表、分隔线，不复制其配色与版式。
```

**第三层：正文里点名调用时机。** 只在真用得上它的镜头写，全文都挂等于没挂。

```
运镜：按 [@符-运镜] 的推拉节奏，从桌面前推到瓶身
```

### 提交

```bash
python scripts/vidu.py submit --prompt-file G01.txt \
  --image 人物/男主.png --image 场景/饭馆.png \
  --image 道具/旧怀表.png --image out/符/符-运镜/panel.png \
  --duration 12 --name G01
```

`--image` 顺序必须对上 pn 编号，符永远最后一位。

### 挂符的三条硬规矩

1. **一张符一件事。** 想同时要运镜和打斗，是两张符。最多挂 2 张。
2. **别让面板进画面。** 真带进去了，把符里那块示意图裁出来当参考图，比整张稳。
3. **不相关就别挂。** 硬挂一张不相关的符，比不挂更糟——它会污染构图。

---

## 做符的三条硬规矩

1. **一张符一个能力。** 想讲「太极拳 + 运镜」，是两张符。
2. **面板上每个字都要能读。** 看不懂的字等于没写，这张符就是废的。
3. **示意人物不是角色。** 除非这个能力本身讲的就是长相、服装、妆造。

python scripts/vidu.py lib
python scripts/vidu.py lib --q 太极
python scripts/vidu.py lib --show 符-太极拳
