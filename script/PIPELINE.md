# 剧本创作流水线 v2（心法路由版）

> **一句话**：心法不再一次性读完，而是**每一步只读这一步用得上的那几条**，写完**立刻按判据自检**。
> 心法原文留在 `references/r1–r7`，本文件只做**路由**（哪步读哪几条）和**判据**（怎么算过）。⛔ 不复制原文，避免两份漂移。

---

## 0. 为什么要有这一层

以前：写一集戏要先读 r1+r2+r3+r4+r6+r7 ≈ **50KB**，实际一定漏；漏掉的通常是最值钱的
`3.14 期待必须兑现` 和 `6.10 十种 AI 味`。

现在：每步只读 **4—8 条、≤6KB**，而且读完要在结论里留痕（见 §0.3）。

### 0.1 三层结构，别混

| 层 | 放什么 | 谁用 | 会不会变 |
|---|---|---|---|
| **心法层** `references/r1–r7` | 怎么好看（原则、判据、反例） | 编剧（AI 在每一步按需取） | 基本不变 |
| **工艺层** `references/r5·r6` | 怎么做（五步、八条硬规则、常见病） | 编剧（动笔时） | 慢变 |
| **母设层** `bible/00–04` | 什么不能改（万集/苏薇/轮回规则） | 所有人 | **不可变** |
| **机检层** `scripts/ir-*.mjs` | 合不合规（17 门 / 12 门） | 脚本 | 随时可改 |

### 0.2 双轨：心法管「好不好看」，脚本管「合不合规」

```
心法自检  ✅ 但机检 ✗  ⇒ 不可交付（解析不了、时长不对）
机检     ✅ 但心法 ✗  ⇒ 不可交付（能解析，但没人看）
两条都签，才进下一步。
```

### 0.3 读取纪律（三条，最容易被跳过）

1. **只读当步的清单**。清单外的条目可以翻，但**不许以「多读几条更稳」为由整库通读** —— 读多了等于没读。
2. **先声明后动笔**。动笔前写一行：`本步依据：O03 / O07 / O13`（ID 见各阶段自检表）。没有这行，视为没读。
3. **自检逐条答是/否**。答「否」只有两种合法处理：**改**，或**写明为什么不改**（例："B09 否，但本集是刻意的喜剧回弹，已在 warnings 登记"）。⛔ 不许整体答"基本符合"。

## 1. 总图

```
        ┌─ 入口①一句脑洞 ─┐
用户输入 ┼─ 入口②小说/成稿 ─┼→ [0 判入口] → [A 世界篇] → [B1 骨架] → [B2 细版] → [B3 分集] → [C 逐集剧本] → [D 交付]
        └─ 入口③已有成稿 ──┘                              ↑拍板        ↑拍板                    ↑每批≤3集
                                                                                    ↓
                                                                    [P 剧本加工支线]（只补时长/分集/格式）
```

| 阶段 | 产物 | 机检 | 停不停 |
|---|---|---|---|
| 0 判入口 | 任务卡（一行） | — | 不问 |
| A 世界篇 | `world.json` | 无（母设七问人工） | **停** |
| B1 骨架 | `outline.json`（骨架） | `--stage beats` | **停·拍板三件事** |
| B2 细版 | `outline.json`（细） | `--stage beats` | 不停 |
| B3 分集 | `outline.json`（episodes） | `--stage full`（17 门） | 不停（每批≤10集） |
| C 逐集 | `script.json`（scenes） | 12 门 | 不停（每批≤3集） |
| D 交付 | `.docx` / `.md` / `shots.json` / 资产清单 | 再跑 full | 停 |
| P 加工 | `带时长剧本` / `分集` | ⚠ 暂无 | — |

## 2. 阶段卡

### 阶段 0｜判入口（30 秒，别问用户）

**读**：无。

**判**（内部做完就往下走，只在真拿不准时问一句）：

| 用户说 | 入口 | 走哪条 |
|---|---|---|
| 「我有个脑洞」「想让你写个短剧」 | ① | A → D |
| 「这是我写的小说」「按这个改」 | ② | A（`origin=novel`，做锚点映射）→ D |
| 「剧本我写好了，帮我拆成能拍的」 | ③ | **P 支线** → 交接 |

**产出**：任务卡一行 → `入口① ｜ 60 集 ｜ 75 秒/集 ｜ 核心商品：笑+反差 ｜ 主线：不推进`

### 阶段 A｜世界篇初始化

**进入**：入口①②。**已有确认过的 `world.json` ⇒ 跳过。**

**读**（6 条，约 4KB）：

| 心法 | 读它干什么 |
|---|---|
| `bible/00` + `02` + `03` | 母设边界、固定资产、锚点纪律（**不可改**） |
| §3.1 | 决定「观众为什么进来、能得到什么」 |
| §3.2 | 定本篇的**核心商品**（后面所有门都按它查） |
| §3.3 | 允许偏科：只做强一样，别样样平庸 |
| §3.4 | 允许狗血夸张，但五件事要托得住 |
| §5.1 | 拿掉「轮回」两个字，这篇还成立吗 |

**写**：`world.json`（十项，见 `schema/world.schema.md`）

**心法自检**

| # | 判据（答是/否） | 否 → 怎么改 |
|---|---|---|
| A01 | 能用一句话说出「观众进来图什么体验」？ | 回 §3.1 四问，答不出说明核心创意没定 |
| A02 | 核心商品是一个**具体体验**（笑/甜/爽/怕），不是一个题材名？ | 改 `coreValue`，改成体验词 |
| A03 | 敢不敢承认「这一篇只做强一样，其他够用就行」？ | 删掉次要追求，别在设定里凑全能 |
| A04 | 五个托底（动机/能力规则/信息来源/结果成立/不复原）都过了？ | 逐条补，别用"这是喜剧"当免修券 |
| A05 | 拿掉「轮回」二字，这个故事还好看吗？ | 不好看 ⇒ 回 §5.1，本篇卖点没立住 |
| A06 | 主角这一世是**主动选择**了这个身份，还是被剧情推来的？ | 被推 ⇒ 补一个他的选择 |

**机检**：无（母设七问人工，见 `r7` §一）。**⛔ 停下等确认。**

### 阶段 B1｜骨架（五步）

**心法自检**

| # | 判据 | 否 → 怎么改 |

| B1a | 只留了一条主线？其他线是删了，不是"留着不用"？ | 回第 1 步，重砍 |
| B1b | 每个角色的欲望能一句话说清，且和别人不撞？ | 撞了就合脸，或降为 `functional` |

| B1d | 爽点表里有没有连续 3 集以上的真空？ | 补 minor，或把后面 major 前移 |
| B1e | 大爆点落在哪一集？它是 B10（§3.16）说的"峰值"吗？ | 没定就是没拍板 |

**机检**：`node script/scripts/ir-outline.mjs validate outline.json --stage beats`

### 阶段 B3｜分集梗概（每批 ≤10 集）

**读**（6 条，约 3KB）：

| 心法 | 读它干什么 |
|---|---|

| §4.5 | 开局只释放必要信息，别开讲座 |
| §4.9 | 集尾续看机制：每集最后留什么 |

**写**：`outline.json` 的 `episodes`（`synopsis` 叙述体 / `hook` / `suspense` 三栏，缺一栏就是没写完）

**心法自检**（每集四问，逐集填）

| # | 判据 | 否 → 怎么改 |
|---|---|---|
| B3a | 这一集卖的东西，和大纲承诺的 `coreValue` 对得上？ | 对不上 ⇒ 这集在跑偏，重写梗概 |

| B3c | 上一集的大结果，这一集有没有继续算数？ | 没有 ⇒ 补一句"后果"或改上一集 |

### 阶段 C｜逐集剧本（每批 ≤3 集）

**进入**：大纲 17 门全过。

**读**（8 条，约 6KB）：

| 心法 | 读它干什么 |
|---|---|
| `r6` 八条硬规则 | 时长预算、单句≤35、谁的话像谁、动作要常见、每场一个动作、钩子在运动中、结尾悬念、爽点要有戏扛 |
| §3.17 | 对白服务人物的行动和情绪，不是解释剧情 |
| §6.9 | 对白必须**改变互动**：说完之后关系/信息/位置有变化 |
| §6.10 | 十种 AI 味，逐条扫（总结人生道理、人人会自我剖析、句式雷同…） |
| §6.11 | 小动作进括号，改变剧情的动作进 △ |
| §6.12 | 连续对白要不要抢话/打断/留白 |
| §3.8 | 高值节点允许情绪拉满，别自己压回去 |

**写**：`script.json` 的 `scenes`（scene → beats → 台词/动作）

**心法自检**（每集一份，逐集填）

| # | 判据 | 否 → 怎么改 |
|---|---|---|
| C01 | 时长落在目标 ±15%？（先算再写，不是写完再看） | 超 ⇒ 砍动作拍；欠 ⇒ 补冲突不补寒暄 |
| C02 | 每句台词都能一口气说完？ | 拆句，中间插一拍 |
| C03 | 盖住角色名，能认出谁在说话？ | 不能 ⇒ 回 §6.10 第 6 条 |
| C04 | 每个动作都是「生活里常见」的？三件以上物品同时交互有几处？ | 有 ⇒ 换成挑/递/放/推/转身 |
| C05 | 每场至少有一个动作节拍？ | 纯对白场 ⇒ 补一拍画面 |
| C06 | 第 1 拍是**运动中**的具象，不是静物特写？ | 改：抱着箱子跑 ✓ / 抱箱子站着 ✗ |
| C07 | 最后一拍是悬念，不是"收拾东西各自回家"？ | 换最后一拍 |
| C08 | 本集认领的每个 beat，都有连续几拍在演它？ | 只有梗概说说 ⇒ 补戏或退认领 |
| C09 | 每句台词都改变了什么？（信息/关系/位置/风险） | 什么都没变 ⇒ 删 |

| C11 | 高值节点有没有被自己写温了？（该爆的地方爆了吗） | 回 §3.8，把强度提回去 |

**机检**：`node script/scripts/ir-script.mjs validate script.json --outline outline.json`（12 门）

### 阶段 D｜交付

**读**：`r4` 末「定稿前格式七查」+ `r7` §六（正式剧本质量九问）+ `r7` §九（一句话总检）。

## 5. 与旧流程的差异（改了哪）

| 项 | 旧 | 新 |
|---|---|---|
| 心法 | 按章节列 r1–r7，一次性读 | **按阶段路由**，每步 4—8 条 |
