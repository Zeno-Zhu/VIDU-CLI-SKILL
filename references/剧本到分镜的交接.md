# 剧本到分镜：这一刀怎么切

剧本模块（`script/`）和出片模块（本 skill 主线）之间只有一个接缝：**场次。**

- 剧本管到「**场 + 拍 + 台词**」，不管镜号、景别、时长
- 分镜组管「**组 + 镜 + 秒**」，不管剧情怎么编

两边都不越界，中间靠这份文件对齐。**别凭感觉接，下面每一条都是换算出来的。**

---

## 一、先记住两层的分工

| | 剧本（`script/`） | 分镜组（本 skill） |
|---|---|---|
| 单位 | 集 → 场 → 拍 | 集 → 组 → 镜 |
| 时间刻度 | 拍（动作 2.5 秒／句台词按字数） | 秒（单镜 ≥1.2，单组 ≤ profile 上限） |
| 谁定 | 编剧 | 导演 |
| 产出 | `script.json` + `剧本.docx` | `EP01_分镜组.tsv` |

**剧本里出现景别、镜号、机位，就是越界了**——`script/` 的 12 道质量门会拦。反过来，分镜表里改台词的字，也是越界。

---

## 二、源头是 `script.json`，不是 docx

`.docx` 是给用户看的交付件，**机器不读它**。往下走一律读 JSON：

```bash
# 单集剧本（这是接进分镜的原料）
script/examples/示例世界篇/script.json

# 场景清单：场次 + 台词，不含镜号与提示词
node script/scripts/ir-script.mjs render script.json --shots --outline outline.json > shots.json

# 资产清单：人物 / 场景 / 道具，带编号和出现集数
node script/scripts/ir-outline.mjs assets outline.json > 资产清单.md
```

`shots.json` 这一份就是给分镜用的：它已经把「哪一场、谁在、说什么」抽干净了，只差镜头。

## 三、换算：一集 → 几组

### 3.1 三把尺子

| 尺子 | 剧本那侧 | 分镜这侧 |
|---|---|---|
| 集 | 60–90 秒（默认 75） | **5–7 组** |
| 场 | 一场 15–75 秒（短剧常常一场写完整集） | 一场 = 1–5 组 |
| 拍 | 一个动作拍 2.5 秒；一句台词按字数 | 一个分镜 1.5–4 秒（重点镜可到 6 秒） |
| **密度** | **1 集 ≈ 22–27 拍**（样例均值 24） | **1 组 ≈ 4–8 镜（按节奏，不设死线）≈ 4–6 拍** |

**按拍算最准，别按秒算。** 秒数是两边各自估的，拍数是剧本里数得出来的。

```
剧本第 1 集（75 秒，24 拍）
  S01 物业办公室（12 拍）  →  G01 / G02 / G03
  S02 小区广场  （12 拍）  →  G04 / G05 / G06
```

### 3.2 为什么成片会比剧本长一点（必须提前说）

两边算时长用的**不是同一个语速**：

| | 字/秒 | 出处 |
|---|---|---|
| 剧本 | **4.5** | `script/` 的 `charsPerSecond` |
| Vidu 配音 | **3.2–4**（按 3.6 估） | 本 skill 实测口径 |

**同样一句台词，在 Vidu 里占的时间比剧本估的长约 25%。**

但成片也不会正好只长 25%，因为镜头要留呼吸：

```
一集 75 秒的剧本（实测样例：182 字台词 + 24 拍）
  ├ 剧本算法：182 ÷ 4.5 ≈ 40 秒说话 ＋ 10 拍 × 2.5 = 25 秒动作 ≈ 65 秒（余量到 75）
  └ Vidu 算法：182 ÷ 3.6 ≈ 51 秒说话
               ＋ 不承载台词的纯动作镜、反应镜约 30 秒
               ≈ 81 秒（实际切出来 90 秒，因为每镜要留呼吸）
```

**切的时候按 4–8 镜上下组装（示例，按 profile 与节奏定）**：24 拍落到 6 组、每组 4 镜上下，平均一镜 3–4 秒。
一镜别超过 6 秒（除非是有表演的长镜头），也别为了凑镜数把 1 拍拆成两镜。

**结论：一集 75 秒的剧本，出来是 80–90 秒，多一组左右。不会短，也长不了多少。**

**别做的事**：拿剧本标的「75 秒」直接当分镜总时长，切出 5 组 × 15 秒，然后把 24 拍硬塞进去——塞不下。**按拍分组，不按秒分组。**

三条路，开工前让用户挑一条，别自己替他定：

| 路 | 做法 | 代价 |
|---|---|---|
| **A 按拍分**（默认） | 24 拍 ÷ 4 ≈ 6 组，成片 80–90 秒 | 比剧本长十来秒，多花一组额度 |
| **B 压回剧本时长** | 砍掉 1–2 组，删 15–20% 的台词 | **删句必须问过用户**，只能整句删，不许改字 |
| **C 拆集** | 一集剧本拆两集出片 | 每集要单独做钩子和悬念，剧本得回头补 |

### 3.3 单集换算速查

| 剧本单集 | 拍数 | 台词量（约） | 分镜组数 | 成片时长（约） |
|---|---|---|---|---|
| 60 秒 | 19 拍 | 145 字 | 5 组 | 65–75 秒 |
| **75 秒（默认）** | **24 拍** | **185 字** | **6 组** | **80–90 秒** |
| 90 秒 | 29 拍 | 225 字 | 7 组 | 95–105 秒 |

### 3.4 一个真表，对着看

`script/examples/示例世界篇/EP01_分镜组示例.tsv` —— 就是上面那集剧本切出来的，可以直接打开。

| | 数量 |
|---|---|
| 剧本（EP01） | 75 秒 / 22 拍 / 1 场 |
| 切出来 | **6 组 / 24 镜 / 90 秒** |
| 体检结果 | 错误 0，警告 0 |

这张表带**站位列**（第十列），可以对着看「站位预演」怎么写：每镜写谁、在哪个空间锚点（必要时补画面位置）、朝哪、机位在哪一侧。
第一镜写全，后面只写变化；跨组接不接得上，顺着往下读一遍就知道。

切完自己跑一遍，数字对不对一眼就知道：

```bash
python scripts/storyboard_check.py "script/examples/示例世界篇/EP01_分镜组示例.tsv"
```

## 四、场 → 组的切法

**一个组只能在一场里。** 跨场的组，模型会把两个空间画成一个，剪出来是穿帮。

```
一场 → 1–5 组，按下面三条切：
① 一场 ≤ profile 上限 → 1 组，别拆
② 一场 17–30 秒 → 2 组，切在「人物关系变化」那一拍（谁占了上风、谁让步了）
③ 一场 >30 秒 → 按剧情节点切，每个节点一组，天然落在优先档（Vidu 12–16s / H3·即梦2.0 12–15s / sd2.5 30s）
   （样例里 75 秒一场的，正好切 6 组）
```

**必须换组的五处**（跟 `references/30-分镜组.md` 一致）：

- 换场、换时间（「三天后」也算）
- 同一场里两条线各说各的
- 有独立音色的发言人 > 3 个
- 超过 profile 的单组上限
- **组首承接不上**——上一组结尾是大动作/甩镜，这一组没法接

**能合就合的两处**：

- 同一场、同批人、连续动作（推门 → 落座 → 抬头）
- 一问一答且中间没动作插入

## 五、拍 → 镜的映射

`script.json` 的 `flow` 里，两种拍交替出现。**映射关系是固定的：**

| script.json | → | 分镜组表 | 注意 |
|---|---|---|---|
| `{"action": "…"}` | → | `内容` 列 + `功能=叙事` | 一拍 ≈ 1 镜，2.5–4 秒 |
| `{"speaker":"C01","line":"…"}` | → | `台词` 列（**逐字**）+ `功能=对白` | 按字数定时长，见下 |
| `{"speaker":"C01","delivery":"…"}` | → | `内容` 列里的表演描述 | **不是台词**，别混进台词列 |
| `{"mode":"vo"}` | → | `台词` 列，标 `（VO）` | 画外音，镜里可以不出现人 |
| `{"mode":"off"}` | → | `台词` 列，标 `（画外）` | 人不在画里但被听见 |
| `scene.title / time / inOut` | → | 提示词的【场景】段 | 场景头四要素 |
| `characters`（C01…） | → | **出场资产列**（写 `CH01` 或名字） | 见第六节 |

**台词定时长的算法（跟剧本不一样，别混）：**

```
镜时长 = 台词字数 ÷ 3.6 + 0.5（气口）
```

例：`"周师傅，这杯水算你的还是算物业的？"` = 17 字 → 17÷3.6 + 0.5 ≈ 5.2 秒。

超过 6 秒的台词镜，要么拆成两镜连着说（同一说话人，别切走），要么砍句（问过用户）。

**一个动作拍可以带一句台词**——人物边说边动，不用拆两镜。但两拍都动作、都超过 3 秒时，拆两镜。

## 六、资产怎么接

剧本用 `C01/C02` 编号，分镜组表用**出场资产列**，提示词用 `pn`。中间由脚本转一次：

```
剧本 characters
  C01 万集        →  资产清单 CH01 万集
  C02 苏薇        →  资产清单 CH02 苏薇
  S01 物业办公室  →  资产清单 SC01 物业办公室
  P01 欠费明细表  →  资产清单 PR01 欠费明细表
                          │
                          ▼
分镜组表「出场资产」列：CH01,CH02,SC01,PR01
                          │
                          ▼  bind_assets.py（P6，零 LLM）
绑定表 pn：pn1=万集 pn2=苏薇 pn3=物业办公室 pn4=欠费明细表
                          │
                          ├─ 提示词【资产盘点】（prompt_assemble 注入）
                          └─ 作业单 images 顺序（jobs_build 抄）
```

**分镜组表必须写出场资产。** 表管镜头怎么切，也管「这一组谁在场」；
不写就等于把「谁在」交给写词时的记忆，必然漏人 / 错绑。

三条规矩：

1. **pn 每组独立、从 1 开始，不跨组复用，不全局定死。** 唯一来源是 `EPxx_资产绑定.json`；
   人和 AI 都不手写。改了表或资产，重跑 `bind_assets.py --freeze`。
2. **剧本里标了「主场景 ✓」的，必须做板**；只出现一次、只露一次脸的不做（见 `references/资产设定板.md`）。
3. **剧本人物的外观不许在分镜里重新描述。** 资产图定了长相，提示词只写「名字 + 参考图绑定」，
   不写发型服装颜色（`prompts/02-标准模板.md`「资产铁律」）。

```bash
# 剧本侧出清单
node script/scripts/ir-outline.mjs assets outline.json > 资产清单.md

# 落成唯一资产表
python scripts/assets_check.py --file "<项目>/00_剧本与提示词/资产清单.json"

# 分镜组表写出场资产后，生成绑定
python scripts/bind_assets.py --storyboard "…/EP01_分镜组.tsv" \
  --assets "<项目>/00_剧本与提示词/资产清单.json" --episode 1 --freeze
```

## 七、三样不许带过去

1. **不许带镜号、景别、时长。** 剧本里根本没有，别从剧本里"读出"镜头——那是导演的活。剧本说「他把杯子推开」，到分镜才决定是特写还是中景。
2. **不许改台词的字。** `script.json` 的 `line` 是唯一真相。可以拆句、可以跨镜连说，**不许改字、加词、删句、换人**。要删得先问用户。
   ★ **本子来自用户（Word / PDF / 微信里贴的一段）时，原文就是唯一真相**：先把原文原样落成
   `00_剧本与提示词/_剧本全文.txt`，之后所有环节都以它为对账基准。
   ⛔ 不许以「整理格式」「统一标点」「顺一下口语」为名改字——**连错别字也照搬**，要改先问用户。
   ⛔ 装不下就拆组，不许为压时长删台词；真要删，用户点头后**只整句删**，并在交付说明里写删了哪句。
3. **不许把 `delivery` 当台词。** 「抹了一把脸，声音很平」是表演提示，进 `内容` 列，不进 `台词` 列。

## 八、交接自检（六条，跑完再动笔）

写第一组提示词之前，逐条对一遍：

| # | 查什么 | 不过怎么办 |
|---|---|---|
| 1 | 每组都只在一场里？ | 跨场的拆开 |
| 2 | 组时长在 profile 优先档，加起来 ≈ 集时长 ×1.1？ | 差太多回第四节重切 |
| 3 | 每组镜数按节奏、第一镜写了站位、出场资产列填了？ | 漏的补上；见 `references/30-分镜组.md` |
| 4 | 每句台词都能在 `script.json` 里逐字找到？ | 找不到就是改了，改回去 |
| 5 | 每个 `pn` 都对应盘点表里一个真实文件？ | 缺的补图，别先用文字凑 |
| 6 | 剧本里标「生成难点预警」的拍，提示词里给了替代方案？ | 见 `script/references/r6-写戏工艺.md` §动作要常见 |

第 6 条最容易漏。剧本写「伸篙一挡、睫毛颤、以寸计的位移」这种，视频模型演不出来——**这不是提示词能救的，得回剧本改成常见动作，或者用镜头语言绕开**（切特写、切反应、切空镜），绕不开就跟用户说这条拍会崩。
