# r4｜格式规范

> 源：《无限轮回宇宙·短剧共创 设定》第六章 6.1–6.18、第八章 8.1–8.3
> **这一份是硬规范。`ir-script.mjs render` 的输出必须逐项符合它，`validate` 会抽查。**
> 写完一集，先按这一份对格式，再谈好不好看。

---

## 6.1 剧本只写可执行内容

正式剧本要让演员、分镜系统和制作团队能理解当前现场发生了什么。

**主要包含：** 场景、人物、可见动作、人物对白、必要声音、重要文字信息、实际剧情结果。

**避免：** 小说式心理解释、作者总结、剧情分析、大段不可拍摄的文学修辞。

### 不要直接告诉观众

- 人物实际上在想什么
- 这一幕象征什么
- 这段剧情为什么重要
- 观众应该产生什么情绪

这些内容应通过**行动、对白和现场结果**体现。

---

## 6.2 单集标题

默认格式：

```
第X集·集名
```

例：`第1集·这次我是猪`

集名应简洁，便于内容识别和管理。不要求标题解释全部剧情。

如果当前项目已经锁定其他格式，以项目格式为准，并在全剧保持统一。

---

## 6.3 场景标题

每个独立场景使用：

```
X-X：[日/夜] 场景名称 内/外
```

例：`1-1：[日] 养殖场猪圈 内`

- 地点或主要时间状态发生明显变化时，建立新场景。
- 同一连续空间中正常的人物移动，不需要机械拆成多个场景。

### 时间标记可取

`日` / `夜` / `晨` / `昏`。极短场景可以只写 `日` 或 `夜`，不要求精确到小时。

---

## 6.4 场景人物

场景标题下标记：

```
人物：角色A、角色B、角色C
```

**只列实际参与当前剧情的人物。**

功能角色可以使用身份称呼：医生、服务员、警察、工作人员、路人。不需要给所有临时人物取正式姓名。

普通背景群众没有独立剧情作用时，不需要逐一列出。

**人物进入、离开、出现和消失的状态，应在正文中保持清楚。**

---

## 6.5 画面与动作格式

所有独立的场景动作与现场变化统一使用 `△` 开头。

动作正文重点写清：

- 谁在行动
- 行动针对谁或什么
- 人物当前的位置和重要视线对象
- 现场发生什么变化
- 动作产生什么可见结果
- 需要表现的情绪反应是什么

**尽量使用演员能够表演、镜头能够拍摄的内容。**

| ✗ 错 | ✓ 对 |
| --- | --- |
| △女人心中终于明白，自己多年付出的感情已经毫无意义。 | △男人把合同推到桌子中央，指着最后一页的签字栏。女人拿起合同，直接撕成两半。 |

需要表现心理时，通过**具体选择、动作、关系和对白**实现。

---

## 6.6 动作颗粒度 ⚠️ 与 JSON 结构的关系

以**完整表演单位**为基本颗粒度。一个自然连续的动作，可以写在同一条 △ 中。

**不机械拆分**这类普通微动作：

抬眼、低头、转身、握拳、呼吸、看向某人、拿起手机。

只有当动作主体、行动阶段、重要物件、现场结果、人物关系或戏剧意义**真正发生变化**时，才考虑拆开。

**判断标准：拆开以后，是否增加了新的剧情、表演或现场信息？如果没有，应优先合并。**

但**重要羞辱、反击、亲密、打斗、奇观和结果兑现，应根据体验需要充分展开**。不能用一句总结代替本应呈现的核心过程。

### 结构上怎么落地

`script.json` 里动作是**细拍**（每个 action 一拍，用于计秒）；`render` 时会**按场把连续的动作拍合并成一条 △**，遇到台词就断开。

所以你写 JSON 时不必操心合并——**该拆就拆，每一拍一件事，让计秒准确**；合并由脚本负责。

---

## 6.7 对白格式

统一采用：

```
角色名（同期动作、视线或必要情绪）：自然中文对白
```

例：`万集（把合同放到桌上）：这份合同我不签。`

**正常对白不要求每句都写情绪标签。** 说话时没有特别需要说明的动作、视线或情绪，直接写：

```
万集：我知道。
```

### 括号里可以放

同期动作 / 当前视线对象 / 明显情绪 / 必要表情 / 身体状态。

### 括号里不可以放

- 大量文学化心理描写
- 复杂的配音指导

> `validate` 的第 12 道门会对「心里／内心／想着／明白／意识到／终于知道」这类词报警。报警不等于错，但多数时候应该改成可见动作。

---

## 6.8 中文对白本土化

默认采用自然、符合中国观众语言习惯的中文对白。不同题材按世界背景调整语言。

| 题材 | 语言要求 |
| --- | --- |
| 现代都市 | 符合人物身份、年龄、职业与现实关系，自然直接 |
| 古代 | 符合时代氛围与人物地位；**不强制所有人说文言文**，也不让人物无理由使用明显现代网络口吻 |
| 玄幻 | 允许符合类型特点的尊称、身份与力量体系语言，避免大量空泛玄学术语 |
| 喜剧 | 可以更生活化、荒诞、夸张，重点保证人物表达与喜剧机制成立 |
| 科幻 | 专业术语按需使用，**避免把人物对白写成技术说明书** |

发生在中国现实环境的故事，应尊重观众熟悉的家庭、社会、职业与文化常识。独立架空世界，不强行套用现代中国现实制度。

**正式中文剧本不需要英文对白，也不需要逐句中文翻译。**

---

## 6.9 对白的实际功能

人物对白应当来自当前交流的真实目标。

说话可以为了：争取、拒绝、试探、解释必要事实、欺骗、隐瞒、威胁、保护、请求、选择、攻击、改变关系，或制造喜剧与其他直接的类型体验。

**避免只为了向观众介绍设定，让人物向已经知道事实的人重复解释。**

人物需要完整表达事实和情绪时，可以自然说完整。不强制每句话缩减到极短。

---

## 6.10 对白 AI 味控制 ⛔

重点防止以下十种问题：

1. 人物频繁总结人生道理
2. 每个人都能准确分析自己的心理
3. 台词过度工整，像提前写好的演讲
4. 连续使用相同句式、反问和狠话
5. 对白只解释剧情，不改变人物互动
6. 不同人物长期采用相同说话方式
7. 情绪表达过于成熟礼貌，削弱原有戏剧强度
8. 为了简洁，把完整意思强行拆成大量单词级问答
9. 为了制造金句，忽略人物当前处境
10. 人物反复确认观众和对方已经知道的信息

**人物可以直接说狠话。** 可以表达愤怒、嫉妒、委屈、欲望和偏爱。不因为台词直白，就自动认为需要含蓄化。

---

## 6.11 对白与动作的分配

| 情况 | 放哪 |
| --- | --- |
| 说话过程中自然发生的小动作、视线、必要微表情 | 对白括号 |
| 动作本身改变剧情、空间、物件、关系或结果 | 独立 △ 正文 |

不要在每句对白之间机械插入无意义动作。也不要把重大剧情动作压缩进对白括号，导致关键事件看不清楚。

**判断依据：动作只是辅助这句话，还是它本身已经成为剧情的一部分？**

---

## 6.12 连续对白与打断

同一个人物围绕同一表达目的连续说话，原则上保持自然完整的对白回合。

只有出现**真实打断、突然事件、情绪变化、改口或表达目标改变**时，才拆分为新的对白回合。

允许抢话、沉默和停顿，但这些应来自当前人物互动，不机械制造破碎对白。

---

## 6.13 重要物件连续性

真正影响剧情的物件，在出现、转移、丢失、损坏、隐藏和状态变化时，需要交代清楚：

合同、手机、武器、戒指、信件、药物、重要证据、系统道具、特殊法器。

不需要详细记录所有生活用品。

> **但重要物件不能前一场还在甲手里，下一场无过程出现在乙手里。**

---

## 6.14 人物与现场连续性

多人场景需要让观众理解：

- 谁在当前空间
- 谁正在行动
- 谁能听见或看见什么
- 谁正在参与交流
- 人物之间处于什么关系和位置
- 谁已经离开
- 谁通过什么方式进入

不要求记录每个人的全部微动作。**只有真正影响人物关系、公开压力、信息传播或剧情结果的反应，才重点展开。**

---

## 6.15 声音与画外内容

电话、广播、录音、设备播放、门外声音和画外人物，**需要写清楚声音来源**。

| 情况 | 写法 |
| --- | --- |
| 角色尚未出现在画面中，但可以被听见 | `角色名（画外）：对白` |
| 角色内部旁白或回顾性叙述 | `角色名（VO）：对白` |

**不能滥用 VO 解释人物心理、重复画面或讲述完整世界观。**

VO 应具有明确叙事价值，并符合说话人物的口吻和当时认知。

> 数据层：`mode: "off"` 渲染成 `（画外）`，`mode: "vo"` 渲染成 `（VO）`。

---

## 6.16 屏幕文字与设备信息

手机、短信、文件、电脑、系统面板及其他文字信息，**只在剧情需要观众明确读取时**呈现具体内容。

如果剧情只需要人物看到信息后作出反应，不必完整展示操作流程和全部文字。

重要信息应保持前后准确一致。

---

## 6.17 场景有效性

一个场景应当具有当前剧情任务或明确观看价值。可用于：

推进事件 / 改变关系 / 暴露必要信息 / 完成人物选择 / 增加重要期待 / 兑现当前核心体验 / 完成有价值的喜剧、人物或情感互动。

**不要求每个场景都产生新的宏观剧情事实。** 但没有推进、没有蓄力、没有即时体验的重复场景，应优先精简。

---

## 6.18 不提前进行分镜设计 ⛔

正式剧本阶段主要负责：人物、动作、对白、场景、声音和剧情结果。

**除非用户明确要求，不在剧本正文中加入：**

景别、镜头编号、机位、焦距、推拉摇移、摄影角度、视频生成模型参数。

分镜制作由后续独立工作流完成。剧本应提供足够清楚的可拍信息，同时保留合理的分镜创作空间。

---

## 第八章｜完整格式模板

### 8.1 基础结构

```
第X集·集名

X-X：[日/夜] 场景名称 内/外
人物：角色A、角色B、角色C

△人物动作、现场变化和可见剧情结果。
角色A（同期动作、视线或必要情绪）：中文对白。

△后续动作、人物反应或现场变化。
角色B（同期动作、视线或必要情绪）：中文对白。
```

### 8.2 格式示例（只演示格式，不构成剧情模板）

```
第1集·这次我是猪

1-1：[日] 养殖场猪圈 内
人物：万集、饲养员

△一头小猪站在猪圈角落，面前摆着一盆猪食。几头成年猪挤过来，把它顶到一旁。
万集（VO）：修仙当过老祖，打仗当过皇帝，连皇帝的爹我都当过。这辈子倒好，直接当猪了。

△万集试图挤回食盆旁边，一头大猪突然撞过来。他脚下一滑，整个脑袋栽进猪食里。
万集（VO）：不是，你们吃个饭还搞竞争上岗？

△饲养员提着饲料桶走到栏杆外，看见万集满脸猪食，忍不住笑了。
饲养员：嘿，这小家伙挺能折腾啊。

△万集抬起头，冲着饲养员张嘴，却只发出一声猪叫。
万集（VO）：行，连说话的资格都没了。

△饲养员翻开记录本，在万集的编号后画了一个圈。
饲养员：这头不错，过两天就送走。

△万集停止挣扎，盯着饲养员手中的记录本。
万集（VO）：送哪儿？

△饲养员合上记录本，拿起手机拨通电话。
饲养员：喂，老王？你要的那批猪，后天就能拉了。

△万集转头看向猪圈里的其他猪，随后猛地扑向栏杆。
万集（VO）：等等！后天？！
```

**执行时不要复制示例中的人物、对白或剧情。** 每部世界篇独立创作。

### 8.3 交付格式

**正式剧本默认交付 `.docx`**，由 `ir-script.mjs render --docx` 直接生成，不需要事后手工排版。

| 元素 | 排版 |
| --- | --- |
| 文档标题 | 黑体 20pt，居中 |
| 集标题 `第X集·集名` | 黑体 16pt，居中，段前段后留白 |
| 场景头 `X-X：[日] 地点 内` | 宋体 12pt，加粗 |
| 人物栏 | 宋体 10.5pt |
| △ 动作 | 宋体 12pt，首行缩进两字 |
| 对白 | 角色名加粗，内容常规，首行缩进两字 |
| 页面 | A4，1.5 倍行距 |

Markdown 只在两种情况下给：用户明确要纯文本，或要把剧本贴进其它创作工具。**别把 md 改个后缀当 Word 交出去。**

正文结构与 Markdown 完全一致（标题、场景、人物、△、对白保持统一），不在正文穿插作者分析和提示词说明。

用户明确要求 JSON、TSV 或其他数据格式时，再按对应协议输出。

## 附：定稿前格式七查

| # | 查什么 | 常见错 |
| --- | --- | --- |
| 1 | 集标题是 `第X集·集名` | 写成 `第一集：` 或漏集名 |
| 2 | 场景头是 `X-X：[日] 地点 内` | 漏方括号、漏内外、用 `-` 代替 `：` |
| 3 | 人物栏非空且只列实际出场 | 把背景群众全列上 |
| 4 | 每个场景至少一条 △ | 整场只有对白（广播剧） |
| 5 | △ 里没有引号台词 | `△他说"我不干"。` ← 错，改成对白行 |
| 6 | 台词行是 `名字：内容` 或 `名字（提示）：内容` | 用 `-` 或加粗当人名 |
| 7 | 没有镜号、景别、机位 | `△特写：手` ← 错，删 |
