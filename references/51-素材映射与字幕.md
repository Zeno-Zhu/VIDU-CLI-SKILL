# 51 · 素材映射与字幕设计

> 来源：`剪映交付-素材映射与字幕设计说明.md`（已并入本文件）。
> 本文说明两件事：① 把时间线交付成剪映可编辑草稿时，如何保证素材路径映射不出错；
> ② 字幕的设计方案（定档、参数、分块、时间、烧录与验收）。
> 面向接手方，可直接按此复现或验收。剪辑决策见 `50-剪辑与交付.md`。

# 第一部分　素材路径映射

## 1.1 问题的本质

剪映草稿是一个 **JSON 工程文件，只存路径，不存素材本体**。时间线上的每个片段都指向一条"媒体记录"，媒体记录里写着素材的绝对路径、时长、分辨率。所以：

- 路径写错 → 草稿能打开、时间线骨架在，但画面全红/全黑；
- 路径写对但**素材池没登记** → 时间线和缩略图都正常，素材区却是空的（这一条最容易漏，见 1.4）；
- 素材被移动/改名 → 草稿不会自动跟随，必须重新生成或改台账。

## 1.2 映射链：三层结构

```
剪辑决策表（片段序号 → 素材ID + 源内入出点）
        ↓  用素材ID查
素材台账（素材ID → 绝对路径 / 时长 / 分辨率 / 帧率 / 有无音轨）
        ↓  按绝对路径写
剪映草稿（媒体记录 + 时间线片段引用媒体ID）
```

**关键设计：决策表里不出现任何路径**，只出现"素材ID + 源内秒"。路径只在台账这一层。这样素材换盘、换目录、换机器时，**只改台账，决策表一个字不用动**，草稿重新生成即可。

台账由素材目录扫描生成，一条素材一行，字段固定为：`ID / 文件名 / 绝对路径 / 时长(秒) / 宽高 / 帧率 / 总帧数 / 是否有音轨`。ID 由文件名归一化得到（去扩展名、去非法字符），保证同一素材在任何机器上 ID 相同。

## 1.3 路径写入规范

| 项 | 规范 | 原因 |
|---|---|---|
| 形式 | **绝对路径**，URI 化后写入（`file:///` + URL 编码） | 草稿根和素材常常不在同一个盘，相对路径必错 |
| 中文/空格/括号 | 百分号编码后再写；回读时解码比对 | 未编码的 `#`、`%`、空格会被解析器截断 |
| 盘符 | 保留原始盘符，不做映射 | 素材搬家就更新台账，不在草稿里做盘符替换 |
| 素材副本 | **不复制**进草稿目录 | 复制会带来第二份真源，后续对不上版本 |
| 时长 | 写素材真实时长，且必须 ≥ 该素材被引用的最大出点 | 出点越界时播放器会静默截断成黑帧 |

## 1.4 素材池登记（"时间线正常、素材区空白"的成因）

剪映的**素材池面板**读的不是时间线那份媒体记录，而是另外两组数据：草稿里的素材清单（按类型分组）+ 虚拟素材库索引。很多人只写时间线，结果素材池永远空白。

规矩只有一条：**素材池记录的 id 必须等于媒体记录的 id**（不是新建一套 id）。写入时从媒体记录反查生成素材池记录，一次登记，两边同源。判断是否登记成功：打开草稿看素材区是否有缩略图；没有就是没登记上。

## 1.5 三道校验闸门（前一道不过，后一道不许跑）

**① 写前校验（对台账）**
- 每个素材ID都能在台账里解析到；
- 文件真实存在、可读；
- `出点 ≤ 素材时长`，越界则夹边并记告警（不静默截断）；
- 分辨率/帧率与工程设置一致（不一致要显式记录，避免混入不同画幅的素材）。

**② 写后回读（对生成的草稿）**
- 媒体记录条数 = 被引用的素材数（不是素材总数，未被引用的不该出现）；
- 每条路径再解码一次，逐个 `exists` 复核；
- 主轨片段**首尾相接**：第 N 段的结束时间 = 第 N+1 段的开始时间，无空隙、无重叠；
- 总时长 = 决策表各段时长之和（容差 1 帧）；
- 字幕轨块数、音效轨条数与决策表对账，少一条就算失败。

**③ 发布后回读（对落到草稿根的副本）**
剪映保存时会**重写草稿结构**：变速信息会被挪进独立的 speeds 表，关键帧被收进片段级的 common_keyframes，字段名和层级都变。所以发布到草稿根后要按"剪映重写后的结构"再核一遍关键字段，而不是拿生成时的结构去找。找不到不代表没写进去，先看新结构里在不在。

## 1.6 隔离与版本纪律

- **先生成在隔离工作目录，校验通过再复制到草稿根**。半成品绝不进用户的草稿列表。
- **只写草稿，不启动剪映**。写草稿是纯文件操作，零副作用；需要成片时再单独执行导出。
- 草稿命名加固定前缀（如 `AI_`）并落一个标记文件，和人工草稿区分开。
- **版本兼容**：剪映较新版本会把草稿转成加密格式，**一旦用新版本打开过，旧版本就读不了了，且不可逆**。所以交付后约定用固定版本打开；被误开过的草稿只能从隔离目录重新发布一份。

## 1.7 常见失败与处置

| 现象 | 真正原因 | 处置 |
|---|---|---|
| 大量"素材路径解析失败" | 台账只有文件名没有路径，或路径没 URI 化 | 补绝对路径；中文路径统一编码 |
| 时间线正常、素材区空白 | 素材池没登记，或 id 与媒体记录不一致 | 用媒体记录反查登记，id 必须相同 |
| 画面红/黑但时间线有片段 | 路径失效（素材被移动）或出点越界 | 更新台账重生成；别在草稿里手改 JSON |
| 校验报"轨道有空隙或重叠" | 上游入出点越界后被夹边 | 回决策表改坐标，不要在草稿层补丁 |
| 关键帧/变速"查不到" | 查错位置（在旧结构里找） | 按剪映重写后的结构查 speeds / common_keyframes |
| 首页看不到新草稿 | 剪映缓存了草稿列表 | 进出一次草稿列表或重启；发布成功 ≠ 首页已刷新 |

# 第二部分　字幕设计方案

## 2.1 先定档，再谈参数

横屏和竖屏**不是同一套参数按比例缩放**，因为三件事不同：信息来源（横屏是坐两米外看一块屏；竖屏是手指划着看，底部还压着平台 UI）、可读字号的物理下限、遮挡环境。

| 判据 | 档位 | 一句话 |
|---|---|---|
| 画幅高 > 宽（9:16） | 竖屏档 | 抢注意力：字大、加粗、粗边、无标点 |
| 画幅宽 > 高（16:9） | 横屏档 | 不打扰画面：字小、常规字重、细边、留标点位置但不显示 |

**两档都不把标点搬上屏**：标点只作断句依据，切完块之后再摘掉。顺序必须是"先切后摘"，摘早了就没法断句。

## 2.2 参数表

| 项 | 竖屏（1080×1920） | 横屏（1920×1080） | 依据 |
|---|---|---|---|
| 字号 | 97px（短边 8.98%） | 56px（画高 5.19%） | 横屏由"单行 + 行宽 ≤ 居中 1/3"反推 |
| 每行字数 | 10 | 10 | 竖屏由 94.4% 行宽÷字宽算得；横屏由 1/3 画幅反推 |
| 行数 | ≤2 | **1（单行制）** | 竖屏留 20.5% 底部给平台 UI；横屏取电影惯例 |
| 单块字数 | ≤20 | ≤10 | 行×列 |
| 块中心 | 画高 74% | 画高 88.5% | 两行下缘 ≈79.5% / 单行下缘 ≈91.4%，都落在安全区内 |
| 字距 | 1 档（≈5% 字宽） | 2 档（每字多 10% 宽） | 竖屏字大不额外撑；横屏靠字距提可读性 |
| 描边 | 24 档（粗边） | 12 档（细边） | 竖屏白底亮场景也要看清；横屏只需从画面分离 |
| 加粗 | 开 | 关 | 粗体在大屏上"喊"，压画面 |
| 阴影 | 明显（α0.55） | 几乎不可见（α0.35） | 横屏只补一层厚度 |
| 读速 | 目标 12 / 上限 15 CPS | 上限 9 CPS | 9 CPS 是中文专属门槛（拉丁字母是 17–20） |
| 块时长 | ≥0.6s | 0.84–7s | 短于 0.4s 会闪 |

**横屏为什么是 56px / 10 字**：横屏有两条互相拉扯的硬约束——只许单行 + 行宽不超过居中 1/3（1920 的 1/3 = 640px）。于是字号和字数只能一起解：

```
字号 × (1 + 0.05×字距) × 每行字数 ≤ 画宽 ÷ 3
56px × 1.10 × 10 字 ≈ 617px ≤ 640px   ✓
```

想放大字号就必须减字数（60px ⇒ 9 字）。单行制的代价是长台词要切 2–3 块顺序显示，换行更频繁；觉得跳，只能降字号换字数，**不要动 9 CPS**。

## 2.3 文本和时间分开取

这是整套方案里最重要的一条：

- **上屏文本用剧本原文**，不用语音识别结果。识别文本会有同音错字（"赔"→"陪"、"一晚"→"一碗"），上屏就是硬伤。
- **时间用语音识别的词级时间戳**。识别文本可以错，但语音活动的时间是准的。
- 一句台词一条字幕；跨镜头的长句，**每个镜头只写自己那半句**，不要在一条字幕里塞两个人或两段话（会导致人名被切成独立字幕块）。
- 台词和画面对不上时，优先信语音时间（它是声画同步的唯一依据），文本仍取剧本。

## 2.4 分块与折行

```
词流 → 标点切成语义单元 → 装箱（每块 ≤ 行×列）→ 超预算再切 → 消孤字 → 上屏
```

规则细节：

1. **以标点为第一优先断点**，其次才是均分。
2. **超长单元按块数均分**，不要切出 1 个字的块（11 字切 6/5，不是 10/1）。
3. **不切断数量词**：切点不落在"个/袋/张/块/间/户/次/天/晚/斤"这类量词前，也不落在数词后（"他连架上有几 / 袋米都没问"是错的，应为"他连架上有 / 几袋米都没问"）。
4. **消孤字**：末块只剩 1 个字时从前一块挪一个字过来；1–2 字的极短块并入相邻块（一块只闪 0.3 秒的"不算"比不显示更糟）。
5. **折行自己插，不指望软件自动折**：无标点的中文长串不会触发自动换行，会直接顶到画面两边。折行时按**可见字数**算预算（标点不占额），并躲开"的/了/着/过"这类不适合做行首的字。

## 2.5 时间分配

- 每个块的起止**按字数在句内的位置映射到词级时间**，不是把整句时长平均分给各块。
  - 例：一句 12 字分两块（6/6），第一块取"第 1–6 字"的词时间起止，第二块取"第 7–12 字"的，中间遇到停顿就自然断开。
- 块时长有上下限：竖屏 ≥0.6s，横屏 0.84–7s；不足时向后面的静音借时间（最多借 0.4s），不许硬压。
- 同一时刻只显示一块，宁可多切几块顺序显示。
- 收尾统一做一次重叠清理：保证任意两块**严格不重叠**（后一块起点 ≥ 前一块终点 + 1 帧），否则写入草稿会被判非法。

## 2.6 样式落到剪映的单位换算（易错）

剪映的字幕样式不是像素，是一套滑杆值和"半个画布高"的坐标系，必须换算：

| 我们的量 | 剪映字段 | 换算 |
|---|---|---|
| 字号（百分比） | TextStyle.size | 直接写百分比（分母取短边时与分辨率无关） |
| 字距 | letter_spacing | 档位值 × 0.05 |
| 行距 | line_spacing | 0.02 + 档位 × 0.05 |
| 描边 | TextBorder.width | 档位 ÷ 100 × 0.2 |
| 阴影 | TextShadow.diffuse | 档位 ÷ 600 |
| 块中心位置 | transform_y | **−（比例 − 0.5）× 2**，单位是半个画布高 |
| 左右边距 | max_line_width | 1 − 2 × 边距比例 |

两个已经踩过的坑：

- `transform_y` **不是百分比**。写 −0.8 得到的是 90% 高——那是"文本"的默认位，不是字幕位；横屏要 88.5% 就写 −0.77。
- **只给白字不给描边，在亮画面上等于没有字幕**。描边 + 阴影 + 定位三样都得写，且不要加任何弹入/缩放动效。

## 2.7 烧录：用 ASS，不要用 SRT

需要"烧死在画面上"的成片时：

- **必须用 ASS**，并在文件头显式声明 `PlayResX / PlayResY = 成片分辨率`。
- 不要用 `subtitles=xxx.srt` 直接烧 SRT：SRT 没有分辨率声明，渲染器会退到默认脚本分辨率（288），字号被放大约 4.67 倍、边距把整行推出画面——**而且渲染器不报错**，成片里一个字都没有。
- 字幕文本与时间轴要**从同一份字幕轨导出**，不要另对一遍 SRT，否则文本和时间会分叉。

## 2.8 验收手法（不要靠描述确认，渲一帧看）

1. **白底看描边**：找一段白墙/天空，描边不够立刻显形。
2. **黑底看字号**：同字同长，字号偏大偏小这一屏最快看出来。
3. **灰渐变看阴影**：亮暗过渡区最能看出描边+阴影是否够。
4. **真实画面看遮挡**：字幕有没有压住人脸、下巴、手里的道具。
5. **长台词看节奏**：20 字以上的台词必然分 2–3 块，看拆分点落没落在语义边界、换行是否太跳。
6. **验证是否真的烧上**：取同一帧做"烧录版 vs 未烧录版"的像素差，强差异区应该是一条**字幕横带**。注意抽帧时 `-ss` 要放在 `-i` 前面并加 `-copyts`，否则时间戳被重置，永远取到 t≈0 那一帧（那时恰好没字幕），会误判成"没烧上"。

# 附：一页速查

**素材映射**
`决策只存ID+源内秒 → 台账存绝对路径 → 草稿存URI化绝对路径`；三道校验：写前对台账、写后回读、发布后再回读；素材池记录 id 必须等于媒体记录 id；只写草稿不启动剪映；隔离目录先生成、校验过再发布。

**字幕**
先定档（横屏 16:9 / 竖屏 9:16）→ 文本取剧本、时间取词级时间戳 → 标点切单元、装箱 ≤10 字（横）/ 20 字（竖）、不切数量词、消孤字、极短块并邻 → 按字数位置映射词时间 → 严格不重叠 → 换算成剪映滑杆值 → 需要烧录时用带分辨率声明的 ASS → 抽帧看五样（描边/字号/阴影/遮挡/节奏）。
