# 符的方法论

`prompts/符的生成.txt` 管的是**怎么把一类经验萃取成一张面板**——那份文件已经很完备，1200 行，把机制、变量、必要/开放的判断都写死了。

这份文件管它没覆盖的三件事：**符之间怎么派生、一张符够不够装、符做完怎么算合格。**

> **运行期的事在另一份：** 锁/变/禁/让四个参数位、主符辅符怎么搭、符和剧本打架谁赢、
> 五维分怎么打 → `references/符-参数卡.md`。做符看这份，挂符看那份。

---

## 一、符有父系

一张符很少是从零想出来的。它通常有三种来源：

| 来源 | 父系登记什么 | 例子 |
|---|---|---|
| 从一张总纲符拆出来 | 总纲符 ID | 从「运镜总纲」拆出「推镜头」 |
| 从一张翻车图反着做 | 那张图的路径 | 「别再这样打光」 |
| 改别人的符 | 原符 ID + 改了哪一条 | 别人的运镜符 + 加了中国剧的节奏 |

**为什么要记：**

- 上游改了，下游要复核。总纲符说"所有镜头都要有起幅落幅"，推镜头符就得跟着核一遍
- 用户问「这张符哪来的」，你答得出
- 攒到三十张时，没谱系就是一堆散图，自己也理不清

**记在哪：** `meta.json` 加一个 `parent` 字段，写上游 ID 或文件路径。**没有就留空，别编。** 编出来的谱系比没有更糟。

## 二、符的三种状态

| 状态 | 意思 | 能当参考图挂吗 |
|---|---|---|
| 候选 | 刚出图，还没人确认 | ❌ 不能 |
| 定稿 | 用户点头了 | ✅ 能 |
| 弃用 | 被新版取代 | ❌ 但**别删图** |

**「做完就自动算定稿」是错的。** 出图成功只说明没报错。自己看一遍、用户点个头，才算定稿。

`meta.json` 里加 `status` 字段，默认 `候选`。`lib` 会显示，也能按状态筛。

**为什么必须有这一档：** 符里装的是知识，知识会变。今天觉得对的说法，做完三条片子可能就发现不对。没有「候选」这一档，你会拿一张没验证的图去指导几十个镜头，错了才发现。

## 三、一张符装不下，怎么办

**量化标准：一张 16:9 别超过 6–7 个信息区块。**

区块 = 一块独立的视觉单元。一个标题、一组要点、一张示意图、一段对错对比，各算一块。超过 7 块，字一定会小到看不清——这不是排版问题，是容量问题。

超过了的处理顺序，**别搞反**：

1. **先删**：重复解释、背景知识、AI 本来就懂的常识
2. **再收**：把范围从「运镜」收窄到「推镜头」
3. **最后才拆**：拆成上篇 / 下篇，两张都进库

拆篇命名：`符-运镜-上` / `符-运镜-下`，下篇的 `parent` 写上篇。

**永远不要做的**：缩小字号硬塞。看不懂的字等于没写，这张符就是废的。

## 四、总纲符：一类能力怎么既统一又分得开

这是最有价值的一条。适用于**管一类事、而不是一件事**的符。

结构固定两段：

- **A. 共同遵守**：这一类能力里，任何做法都不能破的
- **B. 差异化轴**：这一类能力内部，靠哪几个轴拉开区别

以「运镜总纲符」为例：

```
【A 共同遵守】
1. 每个镜头必须有明确主体锚点，观众视线落点只有一个
2. 起幅和落幅都要稳，中间才允许动
3. 运动跟着叙事目的走，不为动而动

【B 差异化轴】三条轴，任意两种运镜至少拉开两条
轴1 与主体的距离：靠近 / 远离 / 不变
轴2 运动方向：横向 / 纵向 / 环绕 / 静止
轴3 速度曲线：匀速 / 加速 / 减速 / 变速

【反趋同铁律】
任意两个镜头，不看内容只看构图走势，也必须能分辨。
两个都是缓慢横移的中景，就是没拉开。
```

**什么时候用总纲符，什么时候用单点符：**

| 你要的 | 用哪种 |
|---|---|
| 「所有镜头都要有起幅落幅」 | 总纲符，管全体 |
| 「推镜头怎么推才不假」 | 单点符，管一种 |
| 两个都要 | 两张，总纲 + 单点，单点的 `parent` 是总纲 |

**为什么这个结构好用：** 单点符的通病是"只讲一条，覆盖不了一类"；想覆盖一类，又容易变成一堆没有重点的清单。总纲符用「A 约束 + B 分化」把两件事分开了——统一的部分写死，分化的部分给轴。

这是从多参BUDDY 的「角色造型规范」搬过来的：它用「共同遵守·全员铁律」+「差异化轴·防趋同」，解决一群角色怎么既像一家人又分得清。同一套思路，放在符上一样成立。

## 五、符做完算不算合格

**三道闸，一道都不能跳：**

| 闸 | 谁做 | 看什么 |
|---|---|---|
| 1. 机器闸 | 脚本 | 出图成功、分辨率对、没报错 |
| 2. 自查闸 | 你 | 中文错字 / 冒出写实人脸 / 塞太满字太小 |
| 3. 用户闸 | 用户 | 这张符讲的**知识本身**对不对 |

**第 3 道闸不能省，也不能自己代劳。** 你能判断它清不清楚，判断不了它讲的知识对不对——那是用户的事。自己替用户点头，等于把一张没验证的图推进生产。

问法要具体，别问「你觉得怎么样」：

> 这张符讲的是你那个意思吗？哪一条说错了，或者哪条其实不重要？

**脚本返回 success，不等于这张符能用。** 自动跑通了只管机器闸，后面两道还得人过。

### 第 3.5 道：五维分（只给定稿打，候选不打）

三道闸管「能不能用」，五维分管**「值不值得留」**。每项 20 分，满分 100：

| 维 | 问句 |
|---|---|
| **D1 可复用性** | 换个剧本、换组人，还成立吗？还是只对那一个案例有效 |
| **D2 控制力** | 真控制住生成结果了吗？还是写了一堆形容词 |
| **D3 清晰度** | 能不能一眼看出「做什么、按什么顺序、做到什么算完」 |
| **D4 参数完整度** | 锁/变/禁/让四个位齐不齐、有没有互相冲突 |
| **D5 稳定性设计** | 身份一致、动作连续、物理关系、风格污染，考虑了吗 |

| 级 | 分 | 怎么处置 |
|---|---|---|
| S | 92—100 | 母符级，可以往下拆子符 |
| A+ | 86—91 | 重要生产任务直接用 |
| A | 78—85 | **定稿门槛** |
| B | 65—77 | 还是候选，补参数再评 |
| C | 0—64 | 当灵感，别进生产 |

**规矩三条：**

1. **A（78）以下不许标 `定稿`。** 标了就是拿没验证的图指导几十个镜头。
2. **设计评级 ≠ 实测评级。** 没跑过片子，只能说「设计 82 分」，不能说「实测 82 分」。
3. **不要求每张都打分。** 一次性的小符（「开水倒进杯子怎么拍」）用户点头就定稿，别走五维。

分数写进 `meta.json` 的 `score` + `grade`，`lib --grade A` 能筛。

## 六、一张符的生命周期

```
候选 → 用户点头 → 定稿 → 用了几次发现不对 → 出 v2 → v1 标弃用（不删图）→ v2 定稿
```

**换版不删旧图。** 图永远留在硬盘上，只改 `_库.json` 里的 `status`。

理由很实在：旧版是证据。用户说"上次那张更好"，或者你自己想知道"当初为什么这么定"，全靠它。
