# 分镜组与分镜：先算清时长，再动笔

设定板确认之后走这一步。**这一步出来的表，决定后面所有提示词的样子。表错了，词全白写。**

---

## 一、先把数字记死

| 项 | 值 | 性质 |
|---|---|---|
| **一个分镜组** | **≤ 16 秒** | 平台硬线，超了提交就报错 |
| 分镜组目标区间 | **12–16 秒** | 落在这里最稳，一致性成本最低 |
| **单个分镜** | **≥ 1.2 秒** | 再短模型来不及立主体，切出来是一团糊 |
| 单组分镜数 | 2–6 个，推荐 **3–5 个** | 少于 2 是浪费，多于 6 每镜都不到 2 秒 |
| 一组素材 | ≤ 9 张图、≤ 3 条音色 | 平台限制 |
| 一组提示词 | ≤ 2000 字 | 平台限制 |

**组是提交单位，分镜是画面单位。** 一条 Vidu 任务 = 一个组 = 里面装着好几个分镜。

---

## 二、为什么是「12–16 秒」而不是「4 秒也行」

平台允许 1–16 秒，但 4 秒一组有代价：

- **组数翻倍**。同样 60 秒戏，16 秒装 4 组，4 秒要装 15 组，提交次数、排队时间、失败重跑的几率全都乘四
- **人物更容易漂**。每组都是独立生成，组越多，见到同一个人的次数越多，总有一次不像
- **接不上**。短组之间没有共同画面锚点，剪起来是一块一块的

反过来，超过 16 秒是不可能，硬塞只会被拒。

所以：**能装满 12–16 秒就别拆碎。** 剧情节点本身就是十几秒一个起伏，按节点拆天然落在这个区间。

---

## 三、组里怎么装这几个分镜

一个组只讲一件事，但这件事要用几个镜头讲完：

```
G01（14 秒）＝ A1 全景交代空间（5s）＋ A2 中景人物进门（4s）＋ A3 近景表情落点（5s）
```

三条分配原则：

1. **不要平均切。** 3 个镜切成 4.7/4.7/4.7 是最偷懒也最难看的分法
2. **动作多的给长**，纯反应给短。伸手拿东西、推门、转身，这些动作至少要 3 秒才能做完
3. **最后一个镜留落点**。台词说完那一秒要有反应，别在话音未落时切走

**加起来的和必须等于组时长。** 差 0.5 秒，成片就会多出半秒空镜或截掉半句台词。

---

## 四、台词塞不塞得下，先算再写

中文配音**含停顿**大约 **2.5–3.2 字/秒**。Vidu 的配音偏慢，别按真人聊天的语速估。

| 组时长 | 大概能装 |
|---|---|
| 12 秒 | 30–38 字 |
| 14 秒 | 35–45 字 |
| 16 秒 | 40–50 字 |

超了怎么办，两条路：

- **拆组**：一句话说完再开下一组（首选）
- **跨镜连说**：同一说话人把一句话分给 A2、A3 两个镜，中间不切人（次选，气口容易断）

**不要靠加快语速硬塞。** 语速是模型给的，你写「语速飞快」它也不会真快，只会把话吞掉。

---

## 五、表长什么样

一张表，一行一个分镜，落盘 `00_剧本与提示词/EP01/分镜组/EP01_分镜组.tsv`（制表符分隔）：

```
组号	分镜	时长	景别	角度	功能	内容	台词	资产
G01	A1	5	全景	门外平视	叙事	雨夜巷口，男主撑伞停在店门前		pn2
G01	A2	4	中景	过肩，店内向外	叙事	他推门进来，收伞，水珠甩在门口地砖上		pn1,pn2
G01	A3	5	近景	柜台侧平视	对白	老板抬头打量他	老板：吃点什么？	pn1,pn3
G02	A1	4	特写	桌面俯拍	空镜	碗底最后一口汤，勺子搁在碗沿		pn4
G02	A2	6	中近景	过肩，男主视角	对白	男主放下勺子，看老板	男主：多少钱	pn1,pn3
G02	A3	5	近景	柜台侧平推	反应	老板伸三根手指，眼神没抬		pn1
```

九列的意思：

| 列 | 填什么 | 为什么要它 |
|---|---|---|
| **组号** | G01、G02… | 提交单位，一条任务一组 |
| **分镜** | A1、A2…（组内编号） | 提示词里的【镜号A1】要对上 |
| **时长** | 秒，写数字 | 加起来必须等于组时长 |
| **景别** | 大远景/远景/全景/中全景/中景/中近景/近景/特写/大特写 | 查节奏，查是不是一路平 |
| **角度** | 机位在哪、朝哪、多高 | 查跳轴，查是不是一个机位拍到底 |
| **功能** | 叙事 / 对白 / 反应 / 空镜 / 氛围 / 转场 | 查空镜和纯情绪占比 |
| **内容** | 一句话说清画面里发生什么 | 这就是提示词正文的素材 |
| **台词** | 说话人：原话，逐字不动 | 不允许改字，只允许拆句 |
| **资产** | pn1,pn2（对应盘点表顺序） | 提交时 `--image` 的顺序 |

**表就是合同。** 用户点头之后，提示词照表写，不许偷偷加镜、改时长、换角度。

## 六、怎么拆组

按剧情节点拆，**一个组只发生一件事**。

**必须拆的五种情况**

1. **场景切换**——换个地方就是新组
2. **时间跳跃**——「三天后」「当晚」都算
3. **超过 16 秒**——不管多顺，必须拆
4. **两组人各说各的**——同一场里两条线交叉，拆开更清楚
5. **有音色的发言人超过 3 个**——平台只给 3 条音色，第四个人只能没声

**能合就合的两种情况**

1. 同场景、同批人、连续动作（进门 → 落座 → 抬头）
2. 一问一答，且中间没有动作插入

**别按台词句数拆。** 「一句一组」会切出大量 3 秒碎片。按事件拆，一个事件里可以有五句台词。

## 七、表出来之后：审核 → 内部评估 → 改一轮

**这一步的产物不是评价，是改好的表。** 评估过程不给用户看。

### 7.1 跑一遍机器体检

```bash
python scripts/storyboard_check.py "00_剧本与提示词/EP01/分镜组/EP01_分镜组.tsv"
```

它替你盯死那些不该靠眼睛数的东西：

| 它查什么 | 判据 |
|---|---|
| 组超长 | 组时长 > 16s → **错误** |
| 组太短 | < 6s → 错误；6–12s → 警告（能合就合） |
| 分镜太碎 | 单镜 < 1.2s → **错误** |
| 镜数不合理 | 少于 2 → 错误；多于 6 → 警告 |
| 空镜过多（单组） | 空镜+氛围 > 组时长 40% → 警告 |
| 空镜过多（全片） | 空镜+氛围 > 全片 25% → 警告 |
| 纯情绪拖 | 单个无水词的氛围镜 > 4.5s → 警告 |
| 连续没戏 | 连续 3 镜都是空镜/氛围 → 警告 |
| 景别一条平 | 连续 3 镜同景别、或整组只有一种景别 → 警告 |
| 机位一条平 | 连续 3 镜机位没变 → 警告 |
| 单一景别过重 | 全片某景别 > 55% → 警告 |
| 台词塞不下 | 组内台词字数 > 组时长 × 3.2 → 警告 |

**错误必须改到 0，才允许进下一步。** 警告不强制，但每一条都值得看一眼。

### 7.2 再自己看四件事

机器只数得清数字，数不清戏。这四条要自己判断：

#### ① 空镜是不是太多

空镜用来交代时间和空间，但连着三个雨滴、灯笼、水面，就是 MV 不是剧。

**判据**：整片看下来，如果每隔一两个对白镜就插一个空镜，砍掉一半。

#### ② 表演是不是空白

「表演空白」= 这个人站在那里，没有动作，没有台词，镜头就这么看着他。

**典型症状**：`功能=氛围`、`台词=空`、时长 4 秒以上，内容写的是「他沉默着，眼神复杂」。

模型演不出「眼神复杂」，只会给你一张呆脸。**必须有落点**：手指缩了一下、喉结动了、把杯子推开。

#### ③ 纯情绪是不是拖太长

情绪需要时间，但不需要那么长时间。**一个情绪镜超过 4 秒，观众就开始走神**。

处理：压到 3 秒以内，或者拆成「一个动作 + 一个反应」两镜。

#### ④ 角度合不合理

- **跳轴**：两个人对话，A 的镜头在左、B 的镜头也在左，观众会以为他们没面对面。过肩镜要分两边
- **一个机位拍到底**：三四个镜全是「平视、正面、同高度」，剪出来像监视器录像
- **角度和情绪不配**：吵架用俯拍会显得可怜，告别用平视会显得平淡
- **越轴运动**：人物从左往右走，下一镜变成从右往左，方向感就乱了

**判据**：一组里至少两种景别、两种机位；对话戏两个人各占一侧。

### 7.3 只改一轮，而且改到位

**为什么只改一轮**：多了会越改越散，每次都在推翻上一次的取舍。一轮改到位，交表。

**改的时候只动这些**

| 能改 | 不能改 |
|---|---|
| 时长分配、镜数、景别、机位角度 | 台词的字（只能拆句，不能改字、不能加、不能删） |
| 空镜换成反应镜或动作镜 | 剧情事实、人物关系 |
| 补一个动作落点、删一个多余镜 | 已跟用户确认过的资产 |
| 组边界（拆组或并组） | 组号（改了后面全断链） |

**改完再跑一遍体检**，错误回到 0。

### 7.4 交表时说什么

**不输出评分，不输出问题清单，不输出「我检查了四个方面」这种过程汇报。**

只说两样：

1. **终版表**（给用户看）
2. **动了哪几处**，一句话一条，3–5 条

例如：

> 表改好了，动了四处：
> - G03 原来 18 秒，拆成 G03 / G04 两组
> - G07 中间三个空镜砍成两个，第二个换成老板抬眼的反应
> - G11 结尾那个 5 秒沉默压到 3 秒，加了一个把茶杯推开的动作
> - G12 两个对话镜原来都在左侧，右边那个改成过肩反打

**不要说**「我按六个维度做了评分」「综合得分 82 分」。用户不关心你怎么审的，只关心表能不能用。

---

## 八、表确认之后

用户点头，这张表就冻结了：

- 提示词按组写，一组一段，镜号与表一一对应
- 提交按组交，`--duration` 用表里的组时长
- 出片后发现某组崩了，回来只改这一组的表和相关提示词，不动其他组

**表冻结之后还改，必须告诉用户改了哪几处。** 悄悄改是最伤信任的做法。

## 九、常见问题

**一组装不下，又不想拆**
→ 先砍空镜和纯情绪，这两类最容易压。压完还超，就必须拆——平台不给你商量的余地。

**台词太少，组里没话说**
→ 说明这组是纯视觉段。要么压到 10 秒以内并进相邻组，要么补一个动作节拍（人物做完一件事再走）。

**分镜数到了 6 个还是超 16 秒**
→ 不是镜数问题，是这场戏本来就有两件事。拆组。

**用户就想一句一组**
→ 跟他说清楚代价：组数翻三倍、人物更容易漂、排队更久。他还坚持，就照做，但别在出问题后说「我早说过」。

**审核改完，用户觉得不如原来**
→ 把两版并排放，让他说哪一版。别争，表是他的。
