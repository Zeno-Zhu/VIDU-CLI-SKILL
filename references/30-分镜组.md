# 30 · 分镜组

> 这一份管「怎么把剧本切成能提交的组」。切错了，后面写词、绑定、提交全是返工。
> 数字只认 `20-渠道参数.md` / `项目配置.json` 的 profile。

---

## 一、先选级

| | L1 精简 | L2 深度 |
|---|---|---|
| 产物 | 一张表（三列 / 九列 + 出场资产） | 表 + `统一制作基准.md` + `镜头规划_{制式}.tsv` |
| 适合 | 单集、对话为主、只做一抽 | 多集、动作 / 多人 / 复杂走位 / 两抽以上 |
| 成本 | 半小时一集 | 2—3 倍，返工少 |

判据：**要逐镜写景别机位运镜（标准 / 两抽）⇒ L2；只走自己人、单集、对话戏 ⇒ L1 够。**

---

## 二、组的基本规则

1. **一个组只发生一件事。** 两个独立叙事任务 ⇒ 拆组。
2. **一个组只在一场里。** 跨场 ⇒ 拆（换场、换时间都算）。
3. **组时长 = 组内各镜之和**，整数秒；不超过 profile 的 `group_max_s`。
4. **单镜 ≥1.2s**；单镜 ≤6s（30s 档可到 8s），超过要有持续观看价值。
5. **镜数不设硬上限**：按节奏定；建议上限见 profile（Vidu 10 / 30s 档 14）。
   一组只有 1 镜判错；2—3 镜只告警。
6. **长对白加反应镜 / 细节特写**：连续 3 句以上对白，至少 1 个反应镜或细节镜，
   ⛔ 不许一镜念到底。
7. **发言者 ≤3**：第 4 个有独立音色的说话人 ⇒ 拆组，或让他只出现不说话。
8. **出场资产列必填**（见第四节）。

---

## 三、时长怎么定

| 渠道 | 上限 | 优先 | 组最小 |
|---|---|---|---|
| Vidu Q4 | 16s | 12–16 | 4s |
| H3 / 即梦 2.0 | 15s | 12–15 | 4s |
| 即梦 2.5（API） | 30s | **固定 30** | 15s |
| Wan3 | 30s | 用户指定 | 4s |

- **优先档是偏好，不是硬门**；低于优先档允许，一集最多一两组。
- **30s 固定档**：所有组 = 30s；`storyboard_check.py` 会拦「≠30」；按 30 秒**重新规划内容密度**，不是把 15 秒的组拉长。
  不够 30 秒：用反应镜 / 细节特写 / 空间镜补，⛔ 不用空镜凑、⛔ 不删台词。
- 台词装不下 ⇒ 拆组；⛔ 不靠加速语速硬塞。
- 台词语速按 **3.6 字/秒**估：12s≈43 字，16s≈58 字，30s≈108 字。

**别按台词句数拆。** 「一句一组」会切出大量 3 秒碎片。

## 四、出场资产列（P6 的输入，必填）

九列表加第 11 列：

```
组号  分镜  时长  景别  角度  运镜  功能  内容  台词  站位  出场资产
G01   A1    5     中景  …     …     …     …     …     万集｜…  CH01,CH03,SC01
G02   A1    6     近景  …     …     …     …     …     …        CH01:寿宴,SC02:灶台区
```

规则：

- 只写**资产名或 id**，⛔ 不写 pn（pn 由 `bind_assets.py` 分配）。
- 多状态角色写 `名字:状态`；不写状态时取本集命中的那个；本集命中多个 ⇒ 必须写。
- 场景写 `SC01` 或场景名；子场景写 `SC01:灶台区`。
- 道具只写本组**真的入镜 / 被拿取**的。
- **有台词的角色必须在本列**；`storyboard_check.py` 会拦。
- 这一列推翻旧规则「资产不进表」——旧规则正是漏人 / 错绑的源头。

## 五、站位预演（出表前走一遍，不生图）

**为什么**：模型不知道谁站在哪。不写，它每一镜重新安排位置；两人对话机位一左一右，观众以为没面对面。

写法（第十列）：

- 组内第一镜写全：所有人、机位、门在哪、光从哪来。
- 后面每镜只写变化：谁动了、机位换没换。
- 用**空间锚点**：`柜台后` / `门边` / `沙发左座` / `角色A对面`；⛔ 不写「画左画右」。
- 每次换位置都要有动作由头；⛔ 不许瞬移。

四查：不挡不叠 / 不跳轴 / 接得上 / 走位有理由。
跨组：上一组末镜站位 = 下一组首镜站位（同空间、同侧、同光位）。
默认不出图；三人以上交叉走位、打斗才画一张俯视简图（不进资产库、不当参考图）。
